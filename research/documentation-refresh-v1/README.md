## Exact boundary

TRANSITION.json pins the old and new README digests, the baseline inventory and
the finite added-file list. Its raw SHA-256 is pinned in the new external checker.
The old README is archived unchanged. Eleven later workflow files have one
mechanically derived routing change: check the actual current tree, create a
separate replay worktree, run their original commands there, recheck the current
tree and upload the actual replay outputs plus the current-to-baseline binding.
Action pins, runtime pins, triggers, commands and expectations remain unchanged;
full Git history is required for these routed jobs. Six earlier workflows, including
the frozen Core/historical workflows, remain byte-identical and execute in the
current checkout. They do not require the later root-README transition.

The complete current inventory is checked. All baseline files except README,
those exact workflow transformations and the aggregate inventory remain identical.
The aggregate inventory changes only those named leaf hashes and adds the exact
new files. No entire-directory exclusion, Core exception, historical-manifest
regeneration, old-guard modification or ignored mismatch is introduced.

The replay worktree is a real detached Git worktree at the pinned merged main.
Its complete inventory, manifest and HEAD are verified; an existing conflicting
or dirty worktree is refused, not reset. Current source equality is checked first,
so this cannot silently replay older code after a source change. If executable
code changes in a future PR, this v1 transition refuses it and needs a separately
reviewed version. This deliberate restriction prevents a documentation exception
from becoming permission to bypass source changes.

Both the current checkout and replay worktree retain exactly the same Core,
adapters, policies, expectations, source locks and evidence. Only the current
checkout has this new outer documentation checker. Its controls run directly
there. Legacy backend commands execute afresh in the isolated worktree; recorded
HEADs identify that worktree honestly, not the current documentation commit.
Source equality is not independent execution or independent human review.

Use a full clone and Python 3.12. No download is needed for these checks:

```sh
python -B tools/verify_artifacts.py
python -B tools/documentation_refresh/replay.py check
python -B -m unittest discover -s tests/documentation_refresh -v
python -B -O -m unittest discover -s tests/documentation_refresh -v
python -B tools/documentation_refresh/replay.py prepare
cd build/documentation-replay
python -B tools/pr12_pr13_integration/preservation.py
python -B tools/erc8404/integrity.py

```

The old root README in that worktree describes its own date. Use the updated root
README for the current project overview and additional suite commands. Existing
dependency preparations still apply; preparation does not claim an executed
backend. `build/documentation-refresh/REPLAY.json` records both identities and
the current worktree status. Existing outputs are never deleted by prepare.

The physical negative controls modify only disposable external-documentation,
workflow, evidence or ERC-8004 source copies. They do not mutate ERC-8404 Core.
They attempt both tampering and inventory resealing, requiring an explicit refusal,
a passing pristine control and restored bytes. No crash is called a kill.

This checker assumes its own reviewed code and policy pin are trusted. It is a
repository preservation check, not a signature, provider attestation or protection
against an attacker replacing the verifier and all its trust anchors together.
